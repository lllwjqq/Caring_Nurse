## 1. 项目概述

### 1.1 背景

我国慢病患者基数大、病程长、管理碎片化。患者普遍缺乏持续性、个性化的居家健康管理手段，尤其在多病共存（如 2 型糖尿病 + 高血压 + 高血脂 + 慢阻肺）场景下，指标监测、生活方式干预与随访依从性难以闭环。

### 1.2 产品定位

「贴心小护士」是面向多慢病患者的 **生产级慢病管理平台**：以 **LangGraph 多智能体协作** 为核心引擎，融合 **RAG 知识增强、实时风险预警、知识图谱可视化**，并通过 **语音交互（讯飞 IAT/TTS）** 降低老年患者的使用门槛。产品兼顾「竞赛答辩可演示」与「架构可上线」双目标。

### 1.3 核心价值

- **闭环管理**：数据采集 → 异常预警 → 智能问诊 → 方案生成 → 随访评估，形成完整闭环。
- **适老化**：支持「按住说话」语音提问与「播放语音」播报回复，老年患者无需打字。
- **可解释**：每次问诊展示 Agent 协作链路，多智能体行为可追溯。
- **安全合规**：全链路医疗免责声明，仅提供健康管理建议，不做诊断。

## 5. 功能需求

> 需求编号规则：`FR-<模块缩写>-<序号>`。每项包含 **描述 / 业务规则 / 验收标准**。

### 5.1 用户认证与账户（FR-AUTH）

| 项 | 内容 |
|----|------|
| 编号 | FR-AUTH-01 注册 / FR-AUTH-02 登录 / FR-AUTH-03 会话鉴权 / FR-AUTH-04 免责声明确认 |

**需求描述**
- 用户通过邮箱 + 密码注册（密码长度 ≥ 6），注册时必须勾选知情同意（免责声明）。
- 登录成功后签发 `access_token`（30 分钟）与 `refresh_token`（7 天），采用 JWT（HS256）。
- 前端请求拦截器自动附加 `Authorization: Bearer <token>`；401 时清除令牌并跳转登录页。

**业务规则**
- 密码以 bcrypt 哈希存储，不落明文。
- 邮箱唯一约束。
- 未同意免责声明不可注册。

**验收标准**
- 注册成功后可直接登录；密码错误登录被拒绝。
- Token 过期后接口返回 401，前端自动跳转 `/login`。
- 未登录访问受保护接口返回 401。

### 5.2 患者档案（FR-PATIENT）

| 项 | 内容 |
|----|------|
| 编号 | FR-PATIENT-01 建档 / FR-PATIENT-02 档案查询 / FR-PATIENT-03 档案更新 |

**需求描述**
- 患者首次登录后进入「建档」页（SetupPage），填写：性别、出生日期、身高、体重、慢病类型（多选：糖尿病/高血压/高血脂/慢阻肺）、过敏史、用药情况、紧急联系人。
- 系统据此生成患者「健康画像」（`health_profile` JSONB）。

**业务规则**
- 慢病类型为多选数组，作为后续预警阈值判定与 RAG 检索的疾病维度。
- 一个用户账户对应唯一一条患者档案（`user_id` 唯一）。

**验收标准**
- 建档后仪表盘、问诊、预警均能读取到慢病类型与基础信息。
- 档案可重复编辑并即时生效。

### 5.3 健康数据录入（FR-RECORD）

| 项 | 内容 |
|----|------|
| 编号 | FR-RECORD-01 指标录入 / FR-RECORD-02 生活方式录入 / FR-RECORD-03 记录查询 / FR-RECORD-04 记录删除 |

**需求描述**
- 支持录入生理指标：血糖、血压、体重、血脂、血氧、心率；血压支持收缩压/舒张压双值，血糖支持「空腹 / 餐后 2h / 随机 / 睡前」场景标注。
- 支持录入生活方式日志：饮食、运动、作息。
- 录入后系统**即时评估**并返回反馈（是否异常、预警等级、参考范围、处理建议）。

**业务规则**
- 指标异常判定依据 `alert_thresholds` 阈值表，按疾病 + 指标 + 场景维度匹配。
- 血糖参考范围随场景不同（空腹 4.4–7.0 mmol/L；餐后 <10.0；随机 <11.1；睡前 4.4–8.0）。
- 血压分级基于收缩压（140/160/180）与舒张压（90/100/110）双阈值。
- 录入异常指标时自动触发预警（见 FR-ALERT）。

**验收标准**
- 录入正常血糖返回绿色反馈；录入空腹血糖 12 mmol/L 返回橙色/红色反馈并生成预警。
- 血压以 `收缩压/舒张压` 形式存储与展示。

### 5.4 健康仪表盘（FR-DASHBOARD）

| 项 | 内容 |
|----|------|
| 编号 | FR-DASHBOARD-01 概览 |

**需求描述**
- 首页展示：今日指标、近 30 天趋势图、最近预警（≤5 条）、当前生效管理方案、待办随访数、综合风险等级。

**业务规则**
- 风险等级取未处理预警中的最高级（green < yellow < orange < red）。
- 趋势按指标类型分组返回时序点。

**验收标准**
- 存在未处理橙色预警时，仪表盘风险等级显示为「橙色」。
- 趋势图能按指标类型展示 30 天内走势。

### 5.5 智能问诊（FR-CHAT，核心）

| 项 | 内容 |
|----|------|
| 编号 | FR-CHAT-01 多智能体编排 / FR-CHAT-02 流式回复 / FR-CHAT-03 链路可视化 / FR-CHAT-04 上下文记忆 |

**需求描述**
- 用户以自然语言提问，系统经 **路由 Agent 识别意图** 后分发至对应子 Agent：

| 意图 | 关键词（示例） | 子 Agent | 输出 |
|------|--------------|----------|------|
| 问诊 | 默认 / 症状 | consult（问诊） | RAG 增强的健康建议 |
| 监测 | 录入/记录/数据 | monitor（监测） | 指标分析 + 异常提示 |
| 方案 | 方案/计划/饮食/运动 | planner（方案） | 个性化管理方案 |
| 随访 | 随访/复查/依从 | followup（随访） | 创建随访任务 |
| 预警 | 预警/异常/危险 | warning（预警） | 未处理预警汇总 |

- 问诊与方案意图采用 **SSE 流式输出** token，前端逐字渲染。
- 问诊中若出现「头晕/不舒服/怎么办」，自动联动方案 Agent 生成调整建议。
- 每次 Agent 调用记录 `agent_traces`，前端侧栏展示协作链路（Agent 名 + 动作 + 耗时）。

**业务规则**
- 系统 Prompt 注入：患者慢病、近期指标、RAG 检索到的指南知识。
- 会话按 `session_id` 记忆，保留最近 10 轮历史。
- 所有 AI 输出附免责声明。

**验收标准**
- 提问「最近头晕怎么办？」→ 路由至问诊 → 引用指南 → 联动生成方案，链路可见。
- 提问「帮我制定方案」→ 生成方案并在「管理方案」页可见。
- 无 LLM Key 时自动降级为内置 Mock 回复，系统不报错。

### 5.6 语音交互（FR-VOICE，本期新增）

| 项 | 内容 |
|----|------|
| 编号 | FR-VOICE-01 语音听写（STT）/ FR-VOICE-02 语音合成（TTS） |

**需求描述**
- **按住说话**：用户长按按钮开始录音（浏览器采集 16kHz 单声道，前端编码为 WAV），松开后上传，后端提取 PCM 后调用讯飞「语音听写（IAT）」转写为文本，自动送入问诊。
- **播放语音**：每条 AI 回复提供「播放语音」按钮，调用讯飞「语音合成（TTS）」返回 mp3 音频，前端播放。

**业务规则**
- 语音凭证配置：`.env` 中 `IFLYTEK_APPID / IFLYTEK_API_KEY / IFLYTEK_API_SECRET`（未配置时接口返回 503，前端提示改用文字）。
- 音频时长过短（PCM < 320 字节）返回 400「音频过短」。
- 识别为空返回 422「未能识别出内容」。
- TTS 文本截断至 800 字符；默认音色 `xiaoyan`，语速/音量/音调可配置。
- 讯飞接口鉴权采用 HMAC-SHA256 签名 + WebSocket 通信。

**验收标准**
- 麦克风授权后长按录音，松开自动转写并问诊。
- 点击「播放语音」可收听 AI 回复。
- 未配置讯飞凭证时，语音按钮降级提示，文字输入仍可用。

### 5.7 管理方案（FR-PLAN）

| 项 | 内容 |
|----|------|
| 编号 | FR-PLAN-01 方案生成 / FR-PLAN-02 方案查看 |

**需求描述**
- 方案 Agent 结合患者档案 + 指南知识，生成结构化方案：`diet_plan`（饮食）、`exercise_plan`（运动）、`monitoring_plan`（监测频率），并附用药提醒。

**业务规则**
- 方案以 JSONB 存储，`created_by_agent=planner`，同一时间至多一个 `active` 方案用于仪表盘展示。
- 用药说明固定提示「请遵医嘱，不可自行调整」。

**验收标准**
- 方案页能展示饮食/运动/监测三块内容。
- 新方案生成后仪表盘「当前方案」同步更新。

### 5.8 预警中心（FR-ALERT）

| 项 | 内容 |
|----|------|
| 编号 | FR-ALERT-01 分级预警 / FR-ALERT-02 实时推送 / FR-ALERT-03 预警处理 |

**需求描述**
- 录入异常指标时，**规则引擎**（阈值表）+ **ML 模型**（Isolation Forest 时序异常）联合评估，生成 绿/黄/橙/红 四级预警。
- 预警经 Redis Stream + Pub/Sub 推送，前端通过 WebSocket（`/ws/alerts/{patient_id}`）实时接收。
- 预警支持「标记已读」「标记已处理」。

**业务规则**
- 分级阈值：血糖（7.0/10–11.1/13.9–16.7）、血压（140/160/180 收缩压）、LDL-C（3.4/4.1/4.9）、血氧（≥94/90/85 下限）。
- ML 风险分 > 0.7 时，黄色预警升级为橙色。
- 红级预警文案提示「请立即就医或拨打急救电话」。

**验收标准**
- 录入超标血糖触发橙色预警并实时推送到前端。
- 预警可标记已读/已处理，处理状态持久化。

### 5.9 随访任务（FR-FOLLOWUP）

| 项 | 内容 |
|----|------|
| 编号 | FR-FOLLOWUP-01 随访生成 / FR-FOLLOWUP-02 问卷提交与评分 |

**需求描述**
- 系统每日 08:00（APScheduler 定时任务）为每位无待办随访的患者生成随访任务；也可通过问诊「随访」意图手动创建。
- 问卷含：是否按时服药（布尔）、监测频率（单选）、方案执行评分（1–5）。
- 提交后计算依从性评分 = 方案执行分 / 5。

**业务规则**
- 同一患者仅保留一个 `pending` 随访，避免重复创建。
- 随访完成后记录 `completed_at`。

**验收标准**
- 每日自动生成随访任务；提交问卷后状态变为已完成并显示依从性评分。
- 仪表盘「待办随访数」实时反映未完成数量。

### 5.10 报告上传与 OCR（FR-DOCUMENT）

| 项 | 内容 |
|----|------|
| 编号 | FR-DOCUMENT-01 上传 / FR-DOCUMENT-02 解析展示 |

**需求描述**

**业务规则**

**验收标准**
- 上传报告后，文档页展示文件名、解析状态与抽取到的指标。

## 6. 非功能需求

### 6.1 性能

| 项 | 指标 |
|----|------|
| 接口响应 | 常规 CRUD < 200ms（P95） |
| 流式首 token | LLM 可用时 < 2s |
| 并发 | 单机支持 ≥ 50 并发患者会话 |
| 数据规模 | 单患者 30 天时序数据秒级检索 |

### 6.2 安全

- JWT 认证 + Refresh Token；密码 bcrypt 哈希。
- 接口鉴权全覆盖，患者数据按 `patient_id` 隔离（越权访问返回 404）。
- 环境变量管理敏感配置（`.env` / Docker secrets），仓库不落真实密钥。
- 后续生产需补充：速率限制、审计日志、字段级 AES 加密、HTTPS。

### 6.3 合规

- 所有 AI 输出强制附免责声明，仅提供健康管理建议，不做医疗诊断。
- 注册需用户勾选知情同意。
- RAG 回答强制引用指南来源，降低幻觉风险。

### 6.4 可用性 / 适老化

- 移动端优先，大字号、大按钮。
- 语音输入/播报，降低打字门槛。
- 无 LLM Key 时系统可用内置 Mock 降级运行，保证演示不断。

### 6.5 可维护性 / 可扩展性

- 前后端分离，REST + WebSocket 解耦。
- 多智能体通过 LangGraph 状态图编排，Agent 可插拔。
- 疾病/指标/阈值/知识均数据驱动，新增慢病无需改代码。

## 8. 接口需求

统一前缀 `/api`，Swagger 文档见 `/docs`。

| 模块 | 主要端点 |
|------|----------|
| 认证 | `POST /auth/register`、`POST /auth/login`、`GET /auth/me` |
| 患者 | `GET/PUT /patients/me`、`POST /patients/me/setup` |
| 健康 | `POST/GET/DELETE /health/records`、`POST/GET /health/lifestyle`、`GET /health/dashboard` |
| 多智能体 | `POST /agents/chat`、`POST /agents/chat/stream`（SSE）、`GET /agents/traces/{session_id}` |
| 语音 | `POST /voice/transcribe`（multipart）、`POST /voice/tts` |
| 业务 | `GET /alerts`、`PATCH /alerts/{id}/read|resolve`、`GET /care-plans`、`GET/POST /follow-ups`、`POST/GET /documents` |
| 知识图谱 | `GET /knowledge/graph` |
| 实时 | `WS /ws/alerts/{patient_id}` |

**流式协议**：`/agents/chat/stream` 返回 SSE，事件类型 `trace`（链路）、`token`（文本增量）、`done`（结束，含 session_id/care_plan/followup/intent）。

## 12. 风险与合规说明

- **医疗合规**：AI 输出仅作健康管理建议，红级预警仅提示就医，不做诊断结论。
- **LLM 幻觉**：强制 RAG 引用来源 + 结构化输出校验 + 高风险规则兜底。
- **OCR 准确率**：解析结果支持人工核对编辑，二期接入真实 OCR。
- **语音隐私**：语音数据仅用于转写，不持久化；生产需补充用户授权与合规告知。
- **讯飞依赖**：语音为增强功能，凭证未配置时自动降级为文字输入，不影响核心流程。
