# 贴心小护士 · 输入输出规格（IO Spec）

> 定位：面向老年慢病患者的 AI 输入接入与输出呈现契约，横切所有 agent。
> 边界：本文只定义「输入怎么接、输出必须包含什么、映射到哪个字段」，不规定具体代码实现。
> 文档关系：
> - [`docs/AGENT_DESIGN.md`](AGENT_DESIGN.md)：Agent 架构（上游）
> - [`docs/AGENT_IMPLEMENTATION_SPEC.md`](AGENT_IMPLEMENTATION_SPEC.md)：后端实施规格（本文的落地依据）
> - [`docs/IMPLEMENTATION_SPEC.md`](IMPLEMENTATION_SPEC.md)：前端实施规格（消费本文的输出字段）

---

## 1. 设计原则

1. **输入侧**：能听别让看、能一键别多步、能选别让打字、不确定就追问。
2. **输出侧**：先结论、少术语、分层次、给行动、能听（TTS）。
3. **安全红线**：AI 不确诊、不自行建议改药、不省略危险信号。

> 红线落地说明：
> - **不确诊**：诊断类输出只给「可能方向 + 就医建议」，不使用「确诊 / 就是 / 诊断为」等措辞；
> - **不改药**：可提示「这个药可能不适合您，建议咨询医生」，不给出「停用/加量/换药」的指令；
> - **不省略危险信号**：命中红旗时必须出现在最前，且不可被后续内容覆盖。

## 2. 输入规格

### 2.1 输入分类与路由映射

| 输入类型 | 例子 | Router intent | 处理 agent | 主要风险 |
|---|---|---|---|---|
| 报指标 | 「今天血压 140/90」 | `monitor` | Monitor（抽取模式） | ASR 数字错 |
| 报用药·已服 | 「吃了片阿司匹林」 | `medication` | Medication（打卡） | 药名/剂量错 |
| 报用药·未来 | 「以后每天吃一片阿司匹林」 | `medication` | Medication（建提醒） | 药名/频次错 |
| 描述症状 | 「这两天头晕、腿没劲」 | `consult`（阶段 1）/ `diagnosis`（阶段 3） | Consult / Diagnosis | 表达模糊 |
| 问知识 | 「糖尿病能吃西瓜吗」 | `consult` | Consult + RAG | 编造 |
| 问自己数据 | 「我最近血糖咋样」 | `monitor` | Monitor（分析模式） | — |
| 请求操作 | 「帮我设个吃药的闹钟」 | `medication` | Medication（建提醒） | 误操作 |
| 上传文书 | 病历、出院小结、化验单、处方 | `document` | Document | 术语多 |
| 拍药盒 | 药盒/药瓶照片 | `document` → `medication` | Document（OCR）+ Medication | **阶段 2 暂不支持图片/条码识别** |
| 情绪求助 | 「我有点怕」「不舒服」 | `consult` | Consult（安抚 + Safety 兜底） | 遗漏危险信号 |
| 无效/闲聊 | 「嗯」「在吗」 | `consult` | Consult（轻量） | — |

> 「报用药·已服」写 `MedicationLog`（服药打卡日志）；「报用药·未来」写 `MedicationReminder`（用药提醒）。两者不能混。

### 2.2 处理规则

- **二次确认范围**：只针对「**将写入数据库或执行动作**」的抽取结果（指标数值、药名/剂量/频次、日期）。用户只是**询问**某个数字（如「6.8 算高吗」）时，不弹确认。
- **确认形式**：语音播报 + 屏幕文字同步；由前端 `VoiceConfirmCard` 承载，后端在 `AgentResult.status="needs_confirmation"` 时写 pending。
- **意图模糊**：先追问、不猜；追问话术要短、给选项。
- **危险信号优先**：命中红旗候选时，**先走 Safety（暂停并询问是否拨打 120）**，不进入普通追问；用户拒绝后继续原链路，并保留「如症状加重请立即就医」。
- **无效/闲聊**：轻量回应，不追问。
- **长文/文书**：进入「文书解释」流程（见第 4 节）。

> 注意：「心口疼 / 胸口压榨感 / 喘不上气」属于**红旗候选**，不能按「意图模糊」处理；Safety 判定为非急症（否定/历史/他人）后，才进入普通问诊。

## 3. 输出规格

### 3.1 通用骨架（所有 AI 回复遵守）

| 骨架 | 要求 | 落到 `AgentResult.presentation` |
|---|---|---|
| ① 结论 | 一句话，≤20 字，说清「是什么 / 怎么样」 | `summary` |
| ② 关键信息 | ≤3 条，口语化，数字带「偏高/正常/偏低」 | `key_points` |
| ③ 行动项 | 我现在该做什么（1~2 件具体事） | `action_items` |
| ④ 边界 | 什么情况要就医 + 免责声明 | `boundary` |
| ⑤ 语音版 | 去符号、数字口语化的 TTS 文本 | `tts_text` |

- `reply` 保留为**全文兜底**（供无障碍阅读 / 前端回退），`presentation` 为结构化呈现；
- `actions` 与 `action_items` 的区别：`actions` 是**系统动作**（写库/导航），`action_items` 是**用户该做的事**（如「明早再测一次」）。

### 3.2 分场景模板（示例）

- **报指标**：「您这次空腹血糖 6.8，略高于目标，建议明早再测一次。」
  （确认话术：「识别到空腹血糖 6.8，对吗？」）
- **报用药**：「已记下您吃了阿司匹林，今天的药就齐了。」
- **症状问诊**：「头晕可能和血压波动有关，建议先测一下血压。」
- **知识问答**：「糖尿病可以少量吃西瓜，但要饭后吃、控制量。」（附来源）
- **查自己数据**：「您这周血糖整体偏稳，只有周三那一次偏高。」
- **危险信号**：「这可能是紧急情况，请立即拨打 120 或马上就医。」（放第一句）

### 3.3 语音版规则（后端生成 `tts_text`）

- 由**后端 agent 生成** `tts_text`，前端只负责播放与缓存；
- 去掉括号、箭头、方括号、单位符号；
- 数字口语化：「140/90」→「一百四比九十」；「6.8」→「六点八」；
- 避免英文缩写；
- 句子之间留停顿；
- 先播「结论 + 最重要的一件事」，后续可说「接着说」展开。

### 3.4 呈现规则

- 首屏 ≤3 屏，细节可展开；
- 术语默认折叠，主视图用大白话，原文放「展开看原文」；
- 危险信号永远置顶。

## 4. 病历 / 出院小结解释规格

上传含大量专有名词的病历、出院小结，**不能整段复述，也不能只给一句摘要**，固定输出以下 8 个模块：

| 模块 | 内容 | 现有 `parsed_data` 字段 | 缺失处理 |
|---|---|---|---|
| ① 这次是什么病 | 诊断翻成日常说法 | `diagnoses` | 无则用 `summary_text` 归纳 |
| ② 现在情况 | 好转 / 稳定 / 需注意 | **无** | 新增 `status_text`（LLM 从原文归纳） |
| ③ 最需要注意的异常 | 挑 1~2 个最关键的，标严重度 | `key_abnormal` | — |
| ④ 要吃的药 | 药名、怎么吃、注意什么 | `medications` | — |
| ⑤ 生活注意 | 饮食 / 运动 / 禁忌 | `doctor_orders`（过滤饮食/运动类） | — |
| ⑥ 何时复查 | 时间 + 科室（可一键建提醒） | `doctor_orders`（过滤复查类） | 可生成复诊提醒 |
| ⑦ 出现这些情况马上就医 | 危险信号清单 | `risk_flags` | — |
| ⑧ 建议问医生的问题 | 帮老人列出复诊该问什么 | **无** | 新增 `questions_to_ask`（LLM 生成） |

> 落地要求：`document_parser._extract_medical_record` 的 schema 需补 `status_text` 与 `questions_to_ask` 两个字段；渲染时按 8 模块顺序输出，术语折叠、语音版先播「① + ③/⑦」。

---

## 5. 与业务模块的联动

- 用药信息 → 同步到「用药」页 / 提醒（`MedicationReminder` 或 `MedicationLog`）；
- 复查时间 → 可生成复诊提醒（阶段 2）；
- 危险信号 → 触发 Safety 流程（暂停询问 120 / 立即就医提示）；
- 异常指标 → 进入「监测」页并可能触发预警（`AlertService`）。

---

## 6. 暂不支持的能力（明确降级）

| 能力 | 现状 | 处理 |
|---|---|---|
| 拍药盒（图片/条码识别药品） | 无 | 阶段 2 再评估；当前降级为「OCR 文字 → Drug 库匹配」，识别不到则提示手动输入 |
| 情绪识别/安抚模型 | 无 | 阶段 1 用 Consult 的简单安抚话术；不做独立情绪模型 |
| 复诊提醒自动生成 | 无 | 阶段 2 随 Medication/Planner 一起做；当前仅在文案中提示 |

---

## 7. 验收清单（判断输出是否合格）

- [ ] 老人能否一句话听懂结论；
- [ ] 是否包含明确行动项（`action_items` 非空）；
- [ ] 若涉及危险信号，是否放在最前且未省略；
- [ ] 是否提供语音版（`tts_text` 非空）；
- [ ] 术语是否已折叠、主视图是否大白话；
- [ ] 是否守住红线（不确诊、不改药、不省略危险信号）；
- [ ] 报指标/报用药是否走二次确认；
- [ ] 病历解释是否覆盖 8 模块（缺字段是否有降级文案）。
